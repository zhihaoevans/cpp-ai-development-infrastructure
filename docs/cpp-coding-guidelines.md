# C++ 编码规范

本仓库示例使用 C++17，不使用 C++20 的 `std::span` 或 C++23 的 `std::expected`。标准升级须同步构建配置、文档和 CI。公共约定见[编码规范与检查](coding-standards.md)。

## 生命周期与接口

- **必须**明确所有权。优先使用值类型和 RAII；独占动态对象建议使用 `std::unique_ptr`，只有确有共享生命周期需求才使用 `std::shared_ptr`。
- 裸指针、引用和视图默认表示借用。**必须**说明可空性、可写性、有效范围及能否被保存；不得返回局部对象的指针或引用。
- 建议使用标准容器管理内存；手工 `new/delete` 或 `malloc/free` 必须说明与外部接口等约束及异常路径清理方式。
- **必须**检查整数窄化和长度计算。`static_cast` 只表达转换意图，不保证输入合法。禁止用 `reinterpret_cast` 绕过协议边界、对齐或别名要求。

```cpp
// 错误：返回后对象已销毁。
const Ipv4Header* bad_header() {
  Ipv4Header header{};
  return &header;
}

// 正确：通过值传递结果。
Ipv4Header empty_header() {
  return Ipv4Header{};
}
```

## 失败、异常与对象语义

- 当前解析器用 `std::optional<Ipv4Header>` 表示输入不符合解析条件，不区分具体原因。**必须**检查 optional 是否有值再解引用；需要错误分类时另行设计状态类型，不用合法字段值冒充错误。
- 当前示例没有禁用异常，也没有建立通用异常框架。建议采用本模块的显式结果返回方式处理预期输入错误；新增异常接口必须写明可能抛出的异常、失败后的对象状态与边界处理方式。
- **必须**让析构和清理路径保持可靠；不从析构函数抛出异常。使用 `noexcept` 前确认所有调用路径，不能用它掩盖异常处理缺失。
- 建议遵循 Rule of Zero，让容器和资源包装类管理特殊成员函数；自定义复制/移动时必须说明资源语义，不再读取已移动对象中未由接口保证的值。
- 使用 `nullptr` 表示空指针，适当使用 `const`；头文件不得使用全局 `using namespace`。

## 协议解析契约

`parse_ipv4(data, size)` 的约定：

- 调用者拥有输入；`size` 必须反映从 `data` 起真实可读的字节数。函数不修改输入，也不保存指针。
- 空指针、截断、错误版本、非法头长或数据报长度返回 `std::nullopt`；先检查边界再读取字段。
- 输入必须包含完整 IPv4 数据报，允许其后有额外字节。成功只返回头长度和总长度，不验证校验和、分片语义或传输层协议。

修改契约时必须同步头文件、示例说明和边界测试。添加未经验证的结构体强转不能代替显式字节读取。

## 并发与性能

- **必须**记录共享状态、线程归属和锁顺序；RAII 锁不能自动防止死锁。不得以 `volatile` 代替同步。
- 建议先使用可解释的同步与数据结构；无锁结构、内存序或零拷贝借用需要相应的生命周期和并发证据。
- 性能优化必须记录工作负载与测量环境；不能为未经测量的收益省略输入校验。

评审检查所有权、异常路径、失效引用、并发和 ABI；自动检查只是补充。当前 CI 不含 TSan 或真实硬件性能测试。
