# 建设路径与验收

以能独立运行的项目为起点，逐层缩短从变更到可靠反馈的时间。

| 阶段 | 具体工作 | 验收证据 |
|---|---|---|
| 第 1 阶段：可运行 | 记录工具链与依赖；提供构建、测试命令 | 新环境可按 README 构建和测试 |
| 第 2 阶段：可验证 | 为核心行为增加测试，CI 重复本地入口 | 故意破坏一个断言时，本地和 CI 均失败 |
| 第 3 阶段：可理解 | 补模块图、数据结构、所有权、线程模型和 AGENTS.md | 新成员可定位入口、约束及变更影响 |
| 第 4 阶段：可审查 | 任务说明验收标准；PR 记录验证和风险 | 审查者可复现结果，知道哪些未验证 |
| 第 5 阶段：可观测 | 记录版本、日志、指标与复现输入 | 用测试或运行数据定位已知故障 |
| 第 6 阶段：可度量 | 建立真实任务、性能基线及返工记录 | 跟踪成功率、缺陷和反馈耗时 |

## 一周落地建议

1. 第 1 天：盘点编译器、构建命令、外部依赖和平台，跑通现有测试。
2. 第 2 天：将手工步骤收敛到脚本或 CMake presets，记录可复现环境。
3. 第 3 天：选关键行为、边界和已知缺陷建立测试。
4. 第 4 天：接入 CI，确保失败返回非零状态，禁止靠手工判断结果。
5. 第 5 天：编写架构与 AGENTS.md，用一个实际小任务检验工作流。

不要为了追求工具数量而跳过可复现和可验证的基础；交付标准以项目现状为准。
