# C 编码规范

本文是面向 C 项目的采用指南；本仓库当前没有纯 C 示例，不能将 C++ CI 通过视为本规范已获 C 编译验证。建议新 C 项目明确采用 C17，并记录编译器、目标平台和允许的扩展；旧项目沿用既有标准，升级单独评审。公共规则见[编码规范与检查](coding-standards.md)。

## 接口、资源与错误处理

- **必须**使用模块前缀避免全局符号冲突，例如 `packet_parse`、`PACKET_MAX_SIZE`；仅本文件使用的函数和对象声明为 `static`。
- **必须**写明指针是否允许为空、长度单位及有效范围。数组形参不会携带运行时长度，使用指针加长度显式传递。
- **必须**配对管理 `malloc/free`、文件、锁等资源，说明分配者、释放者和所有权转移时机。失败路径不能泄漏、重复释放或使用已释放对象。
- **必须**检查可能失败的分配和系统调用。建议状态码和输出参数分离，明确失败时输出“不变”还是“重置”；只有接口契约规定时才使用 `errno`。
- 多资源函数建议使用统一清理出口；`goto cleanup` 可以用于按获取顺序反向释放资源。不能跳过初始化后读取未初始化对象。

```c
/* 示例契约：out 必须非空，失败时 *out 保持原值；成功时调用者负责 free。 */
int packet_alloc(size_t size, unsigned char **out) {
  if (out == NULL || size == 0) {
    return -1;
  }
  unsigned char *buffer = malloc(size);
  if (buffer == NULL) {
    return -1;
  }
  *out = buffer;
  return 0;
}
```

上述片段需包含 `<stddef.h>`、`<stdlib.h>`；它展示契约，不是仓库已构建的接口。禁止直接写 `*out = malloc(size)` 后不检查结果，这会使失败输出语义不清，也可能覆盖调用者原有的指针。

## 长度、字符串与二进制输入

- **必须**先检查长度，再索引、拷贝或做指针运算。检查区间优先使用 `offset <= size && count <= size - offset`，避免 `offset + count` 溢出后绕过检查。
- **必须**在分配 `count * sizeof(*items)` 前检查乘法溢出；区分字节数、元素数和包含终止符的容量。
- **必须**明确字符串是否保证 NUL 终止。`strncpy` 截断时不保证终止；有界函数也需要检查返回值和截断语义。禁止对不可信输入无界复制或把输入作为格式字符串。
- **必须**按协议处理字节序。禁止将任意网络缓冲区直接强转为结构体指针读取，忽略对齐、填充、别名和输入边界。
- 使用 `size_t` 表示内存长度，协议字段在目标平台提供时使用 `<stdint.h>` 中的固定宽度整数；窄化前检查范围。

```c
/* 错误：加法可能回绕。 */
if (offset + count <= size) { /* copy */ }

/* 正确：短路判断后做减法。 */
if (offset <= size && count <= size - offset) { /* copy */ }
```

## 宏、头文件与并发

- 建议使用 `static inline` 函数代替可能重复求值的函数式宏；`SQUARE(i++)` 一类调用可能产生未定义行为，不能靠给宏参数加括号解决。
- **必须**使用有模块前缀的 include guard；公开头文件包含自身所需的标准头文件。需要 C++ 调用时提供 `#ifdef __cplusplus` 保护的 `extern "C"`，并验证两种语言的编译和链接。
- **必须**说明共享数据的同步方式和锁顺序。`volatile` 不能替代原子操作和互斥锁；信号处理函数另行遵守异步信号安全限制。

审查时重点检查：失败分支、部分初始化清理、零长度、最大长度、溢出和截断。自动格式与静态分析只能覆盖其中一部分；采用本文的 C 项目还需建立自己的编译、测试和 Sanitizer 入口。
